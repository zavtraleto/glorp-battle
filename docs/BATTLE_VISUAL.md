# Glorp Battle — визуал поля боя «CRT Occult Vector»

Версия 2.0 · 2026-09-18 · этап T4 · статус: переделан под «Dark Terminal»

**Читать вместе со [спекой Dark Terminal](superpowers/specs/2026-09-18-terminal-visual-overhaul-design.md)** — она главнее этого документа во всём, что она описывает. Здесь остаётся то, что ей не покрыто: состояния клеток, существа, атаки, отладка.

Как выглядит бой на экране CRT терминала: поле, клетки, игрок, враги, атаки, HP и урон. Правила боя — [GDD.md](GDD.md), терминал вокруг экрана — [TERMINAL.md](TERMINAL.md). Решения из обсуждения 2026-09-17 помечены `[решение 2026-09-17]`, стартовые значения — `[оценка]`.

---

## 0. Принцип

Графика выглядит так, будто изначально создана для примитивного вычислительного терминала: **геометрическая сетка + крупные пиксели + фосфорные цвета + процедурные оккультные существа + динамические состояния клеток**. Мы не имитируем старый CRT поверх современной игры: scanlines, bloom, chromatic aberration, glitch — не часть базового языка и добавляются потом отдельным постпроцессингом.

- Чёрный фон, **6 цветов** (спека §6.1), плоская заливка; неполная яркость — тот же цвет, приглушённый к фону (дизеринг убран 2026-09-19: мешал чёткому wireframe).
- Крупные пиксели, линии 1–2 px, точки, простые фигуры, примитивный wireframe.
- Каждый элемент читается силуэтом при низком разрешении.
- **Текст на экране вернулся** [решение 2026-09-18]: полоса состояния сверху (HP, счётчик `REFRESH n/m`) и имя первого чипа Attack Queue снизу — спека §8. Светодиодов на корпусе больше нет, корпус утонул в темноте.

## 1. Палитра

Перенесена в [спеку Dark Terminal §6.1](superpowers/specs/2026-09-18-terminal-visual-overhaul-design.md): индексная палитра на шесть цветов, материал пишет индекс в канал R и яркость в канал G, проход палитры берёт цвет из таблицы и сравнивает яркость с порогом Байера.

Здесь важно помнить одно: **яркость сигнального цвета меняется только через `dimSignal()`**. Обычное умножение цвета масштабирует и индекс, и пиксель перекрашивается в другой цвет палитры.

## 2. Рендер

- Три.js-сцена боя рендерится прямо в текстуру CRT (`CRT_RES` 240×320 [оценка]) без сглаживания, затем проход палитры, затем (опционально) эффекты стекла.
- Эффекты стекла (`CRT_SCANLINES`, `CRT_CURVATURE`, `CRT_BLEED`, `CRT_GHOSTING`, вспышка чипа) по умолчанию выключены [решение 2026-09-17]; код и ползунки остаются.
- **Пиксели спрайтов ровные:** масштаб спрайта подбирается каждый кадр так, чтобы тексель занимал целое число пикселей экрана (1× дальше, 2× ближе), центр спрайта привязывается к пиксельной сетке.
- Порядок: поле → метки → заливки состояний → атаки → существа (ближний ряд поверх дальнего) → HUD-слой (HP-сегменты, числа).

## 3. Камера и поле

- Перспективная камера стоит за стороной игрока, низко, и смотрит вдоль поля в глубину (наклон `VIEW_PITCH` = 41°, `VIEW_FOV` = 44° [оценка]). Поле — перспективная трапеция: ближние клетки крупнее, дальние сжимаются; направление «вглубь» очевидно.
- Камера подгоняется так, чтобы поле занимало `VIEW_FILL` по наибольшей стороне; значения выше 1 намеренно выводят край поля за рамку. `VIEW_OFFSET_X/Y` двигают поле, спрайты и эффекты вместе [решение 2026-09-23].
- **Верхняя полоса-резерв** `HUD_BAND` [решение 2026-09-19]: подгонка (`fitView`, `render/viewCamera.ts`) сдвигает поле вниз кадра; `VIEW_OFFSET_Y` добавляет к этому свободную пользовательскую поправку из DBG.
- Поле 3×6: ряды игрока (y 3..5) ближе к камере, ряды врага (y 0..2) дальше.
- Сетка — тонкие светящиеся линии: клетки игрока — фосфор, клетки врага — красные, по фактическому владельцу (захват перекрашивает клетку) [решение 2026-09-17]; граница — красный пунктир там, где меняется владелец.

## 4. Состояния клеток

Клетка — самостоятельный визуальный объект. Состояние каждой клетки считает чистая функция `cellStates()` (приоритет сверху вниз):

| Состояние | Источник | Визуал |
|---|---|---|
| EMPTY | debug | части сетки нет: контур не рисуется, углы-точки |
| BROKEN | дыра в симуляции; debug; каскад при GAME OVER | фрагментированный контур (сегменты с разрывами), мерцание |
| ATTACK | удар проходит через клетку (чип, взрыв, выстрел, волна) | яркая полоса через клетку, акцент или красный, 0,15 с |
| DANGER | телеграф атаки врага | красный контур, пульс, приглушённая заливка |
| SPAWN | появление врага в начале боя | сжимающиеся концентрические квадраты |
| OBJECT | объект в симуляции (камень); debug | wireframe-куб в клетке |
| CRACKED | трещина в симуляции | излом поверх любого состояния, кроме BROKEN/EMPTY |
| ACTIVE | клетка игрока или живого врага | дополнительный внутренний контур цветом своей стороны + редкая заливка |
| AFTER | несколько кадров после ATTACK | контур мерцает |
| NORMAL | всегда | тонкий контур |

BROKEN, CRACKED, OBJECT и владелец клетки берутся из симуляции (`world.field`, `world.objects`); debug-переопределения рисуются поверх.

BROKEN / EMPTY / OBJECT пока только визуал: включаются на любой клетке из DBG; игровые правила панелей — отдельный шаг [решение 2026-09-17].

## 5. Существа

### 5.0. Нарисованные спрайты [решение 2026-09-19]

- Игрок, Mettik, Canodron и босс Monolith рисуются нарисованными спрайтами из `/assets`. В игру идут уменьшенные копии в `src/assets/sprites/`: игрок из `assets/player_v2.png` — 128×128, остальные вписаны в 128×160 с сохранением пропорций рисунка; используется площадное усреднение и жёсткая альфа. Какой вид врага рисуется артом, задаёт `ENEMY_ART` в `render/spriteArt.ts`; остальные враги процедурные (§5.1).
- Арт полноцветный и приглушён под CRT (насыщенность 0,78, яркость 0,9). Он рисуется **отдельным слоем после прохода палитры** (слой `ART_LAYER`), поэтому сохраняет цвета. PNG-персонажи проходят через объектный hologram-материал (`render/hologramMaterial.ts`): исходная палитра остаётся видимой под цветным свечением, контрастными scanlines, тремя широкими и одним быстрым тонким sweep, контуром, edge fragments и редкими прозрачными dropout-кластерами. Затем ghosting и неизменённое стекло CRT ложатся поверх готовой сцены. Процедурные спрайты остаются в сигнальном palette pipeline. Вспышка попадания — сдвиг исходной текстуры к белому, удаление — пиксельный распад по её альфе.
- Ширина на поле: игрок 0,9 клетки, обычный враг с артом 1 клетка, босс ×1,4; высота по пропорции арта.
- Пока арт грузится, на его месте процедурный спрайт; после загрузки виды пересоздаются.

### 5.1. Враги

- Процедурные пиксельные оккультные существа: `seed → 2–3 примитива → симметрия/деформация → пикселизация → красный спрайт` (32×32).
- Примитивы: круги, глаза, щупальца, линии, геометрические фигуры, органы, оккультные символы.
- У каждого врага: крупный силуэт (заполнено ≥ 25% площади), 1 основной цвет (красный), не больше 3 внутренних элементов (дыры фона и один акцент).
- Облик типа фиксирован сидом (`ENEMY_SEEDS`): Mettik, Canodron и Spiker узнаваемы и различимы; DBG может перегенерировать сиды.
- Анимация: покачивание (idle), «вдох» — растяжение в телеграфе, белая вспышка при попадании, распад на пиксели при удалении, концентрические кольца при варпе.

### 5.2. Игрок

- Отдельный нарисованный силуэт 24×32: фосфор + акцентный визор. Мгновенно отличим от врагов и клеток.
- Мигание при неуязвимости; короткий след из линий при шаге; «вдох» при использовании чипа.

## 6. Атаки

Только геометрия: линии, полосы, точки.

### 6.0. Прицел, аура и попадания [решение 2026-09-19]

- **Прицел заряженного чипа** (первый в Attack Queue): клетки, куда он попадёт, если выстрелить сейчас — жёлтые «дышащие» уголки; у пушек ещё бегущий пунктир по колонке до цели. Считается `sim/chips/aim.ts` по тем же формам и правилу первой цели, что и удар (`World.aimPreview()`), и следует за игроком.
- **Аура на персонаже** по типу чипа: пушки — искры заряда перед грудью; мечи — мерцающая дуга над головой; бомбы — бомбочка над головой с искрящим фитилём; волна — рябь от ног; поддержка — поднимающиеся точки; чипы поля — вращающееся кольцо на клетке.
- **Попадание по врагу:** белая вспышка спрайта, шейдерная рябь спрайта 0,3 с, небольшие искры, слабое тёплое свечение по краям стекла.
- **Удаление врага** — заметно сочнее попадания: крупный двухцветный разлёт искр, кольца на клетке, яркое свечение краёв стекла, вспышка и толчок терминала.
- **Свечение краёв стекла** идёт полосой вдоль границ экрана по его прямоугольнику (расстояние до ближайшего края), а не овальной виньеткой.
- **Цифры урона** крупные (`DAMAGE_SCALE` 4) с толстой обводкой: урон по врагам — жёлто-белый, при появлении на размер больше и с подскоком; урон по игроку — красный, ещё на размер больше и первые 0,35 с дрожит.

## 7. HP и урон

- **HP врага** — небольшое красное число с минимальным зазором над верхом спрайта и тёмной обводкой (2026-09-23; раньше число висело слишком высоко): игрок видит точный остаток HP. Над числом — точки уровня вируса.
- **Урон** — крупное пиксельное число (масштаб ×3) в области попадания, поднимается и гаснет: по врагу — акцент, по игроку — красный, лечение — фосфор.
- Рисуются в HUD-слое CRT (2D), позиции — из проекции камеры.

## 10.2. Подводные камни [2026-09-17]

Ошибки, на которые мы уже наступали; проверяйте их при смене стиля.

- **Материалы боя пишут индекс палитры и яркость, а не цвет.** R — индекс, G — яркость (`signal()`); цвет назначает проход палитры. Обычный цветной материал даст неверный цвет после прохода.
- **Не умножайте сигнальный цвет.** `multiplyScalar` масштабирует и индекс в канале R: пиксель перекрасится. Гасить яркость — только `dimSignal()`.
- **Фаска `ExtrudeGeometry` выходит за пределы выдавливания.** Геометрия глубже заказанной с обеих сторон; кассету закрывала её же передняя грань. Нормализуйте по ограничивающему объёму.
- **Наклон CRT назад топит его в подложке корпуса** — подложка отодвинута на `BODY_Z`; меняя `CRT_TILT`, проверяйте зазор.
- **Стекло обязано сохранять пропорцию картинки:** при упоре в ширину уменьшается высота, иначе тексель перестаёт быть квадратным.
- **Вспышка CRT мультипликативная:** плоское прибавление поднимает чёрный фон до серого.
- **Зоны нажатия проецируются камерой** (`mountCorners` + `screenBounds`), потому что панели наклонены. Плоский прямоугольник плана больше не совпадает с тем, куда попадает палец.
- **Прозрачность спрайтов.** Процедурным `SpriteMaterial` нужен `transparent: false`, а исчезновение — через `alphaTest` (`setDissolve`), иначе сигнал становится полупрозрачным. PNG hologram намеренно использует blending только для мягкого halo/fragments; пиксели основного силуэта шейдер делает непрозрачными.
- **Видимость спрайта** сбрасывается в `place()`: если прятать спрайт снаружи (`visible = false`), делайте это после `place`.
- **HUD рисуется после scanline-прохода** (`HUD_SCAN`). Если композитить его до, тонкие цифры «выедаются» строками развёртки.
- **Смешивание в линейном пространстве.** Полупрозрачные подложки (шторка меню) выглядят слабее, чем ожидаешь: альфа 0.9–0.96 вместо 0.6.
- **Текстуры корпуса читаются в sRGB** (`getRGB(..., SRGBColorSpace)`), иначе всё темнеет.
- **Масштаб рендера** считается по короткой стороне **корпуса**, а не экрана (`RENDER_SCALE_SHORT`), иначе надписи на ПК становятся огромными.
- **Картинка CRT рисуется 1:1 с пикселями стекла** (2026-09-19): разрешение цели рендера считается из раскладки в `Terminal.resize`, `CRT_RES_W/H` задают только пропорцию. Фиксированное 320×440, растянутое на ~388 px стекла дробным шагом, делало линии неровными и мыльными — не возвращайте фиксированное разрешение.
- **Эффекты стекла — как у старого игрового CRT:** сканлайны, свечение, ghosting, bleed и хроматические аберрации включены (они дают цветную обводку линий); выключена только маска люминофора (`CRT_PHOSPHOR` = 0).
- **Размер спрайта на поле меняется непрерывно** по перспективе (`spritePixels`), а не целыми множителями текселя: раньше спрайт прыгал ступеньками между рядами. Арт уменьшается через mipmaps, процедурные спрайты — nearest.
- **Арт рисуется после прохода палитры**, поэтому эффекты атак (выстрелы, волны), попавшие на его пиксели, оказываются под ним.
- **Hologram применяется только к PNG-арту на `ART_LAYER`.** Его halo и fragments используют padding внутри sprite quad; `PixelSprite` компенсирует padding масштабом и `center.y`, чтобы силуэт и точка ног не сдвигались. Параметры доступны в DBG → Tuning → hologram; цвет по типу задаётся частичным override в `hologramConfig.ts`.
- **Приоритет состояний клетки** задан одним списком в `cellStates`; DANGER перекрывает OBJECT — камень под телеграфом не виден, это ожидаемо.
- **Панель браузера душит `requestAnimationFrame`.** Для проверок ставьте `__glorp.loop.clock.paused = true` и гоняйте `world.step()` вручную, иначе состояние не доходит до `ACTION` и проверка врёт.

## 11. Тесты

`cellStates` (приоритеты, таймеры, debug), генератор существ (детерминизм, размер силуэта, ≤ 3 элемента), подгонка камеры (все углы поля в кадре, заполнение), сегменты HP, JS-копия функции палитры, раскладка графических сигналов по времени.
