# Glorp Battle — визуал поля боя «CRT Occult Vector»

Версия 1.0 · 2026-09-17 · этап T2.5 (см. [TERMINAL.md §11](TERMINAL.md)) · статус: утверждено к разработке

Как выглядит бой на экране CRT терминала: поле, клетки, игрок, враги, атаки, HP и урон. Правила боя — [GDD.md](GDD.md), терминал вокруг экрана — [TERMINAL.md](TERMINAL.md). Решения из обсуждения 2026-09-17 помечены `[решение 2026-09-17]`, стартовые значения — `[оценка]`.

---

## 0. Принцип

Графика выглядит так, будто изначально создана для примитивного вычислительного терминала: **геометрическая сетка + крупные пиксели + фосфорные цвета + процедурные оккультные существа + динамические состояния клеток**. Мы не имитируем старый CRT поверх современной игры: scanlines, bloom, chromatic aberration, glitch — не часть базового языка и добавляются потом отдельным постпроцессингом.

- Чёрный фон, 3 цвета, плоская заливка, дизеринг вместо градиентов.
- Крупные пиксели, линии 1–2 px, точки, простые фигуры, примитивный wireframe.
- Каждый элемент читается силуэтом при низком разрешении.
- **Во время боя на экране нет текста** [решение 2026-09-17]: только поле, игрок, враги, состояния клеток, HP-сегменты врагов и числа урона. HP игрока и кастом-шкала — светодиоды корпуса. Меню (титул, пауза, итоги) и описание чипа на лотке остаются текстом.

## 1. Палитра

| Индекс | Роль | Цвет | Сигнал в сцене |
|---|---|---|---|
| 0 | фон | почти чёрный `#05070a` | (0, 0, 0) |
| 1 | поле и игрок | фосфорный cyan `#3cffd2` | зелёный канал |
| 2 | враги и их атаки | красный `#ff2a3a` | красный канал |
| 3 | акценты: урон, удар, важные состояния | бледно-жёлтый `#fff4c2` | синий канал |

**Сигнальная схема.** Материалы сцены не освещаются и пишут «сигнал»: канал = роль цвета, значение = яркость (0..1). Проход палитры (шейдер после сцены) для каждого пикселя выбирает канал с наибольшим значением (при равенстве: акцент > красный > фосфор), сравнивает яркость с порогом Байера 4×4 и выводит цвет палитры или фон. Так любая «полупрозрачная» заливка превращается в точечный узор, а цвета остаются плоскими.

## 2. Рендер

- Три.js-сцена боя рендерится прямо в текстуру CRT (`CRT_RES` 240×320 [оценка]) без сглаживания, затем проход палитры, затем (опционально) эффекты стекла.
- Эффекты стекла (`CRT_SCANLINES`, `CRT_CURVATURE`, `CRT_BLEED`, `CRT_GHOSTING`, вспышка чипа) по умолчанию выключены [решение 2026-09-17]; код и ползунки остаются.
- **Пиксели спрайтов ровные:** масштаб спрайта подбирается каждый кадр так, чтобы тексель занимал целое число пикселей экрана (1× дальше, 2× ближе), центр спрайта привязывается к пиксельной сетке.
- Порядок: поле → метки → заливки состояний → атаки → существа (ближний ряд поверх дальнего) → HUD-слой (HP-сегменты, числа).

## 3. Камера и поле

- Перспективная камера стоит за стороной игрока, низко, и смотрит вдоль поля в глубину (наклон `VIEW_PITCH` ≈ 38°, `VIEW_FOV` ≈ 50° [оценка]). Поле — перспективная трапеция: ближние клетки крупнее, дальние сжимаются; направление «вглубь» очевидно.
- Камера подгоняется так, чтобы поле занимало `VIEW_FILL` ≈ 92% кадра по наибольшей стороне и было отцентровано.
- Поле 3×6: ряды игрока (y 3..5) ближе к камере, ряды врага (y 0..2) дальше.
- Сетка — тонкие светящиеся линии (фосфор). Территория врага отмечена красными точками в углах клеток и красной пунктирной линией на границе территорий.

## 4. Состояния клеток

Клетка — самостоятельный визуальный объект. Состояние каждой клетки считает чистая функция `cellStates()` (приоритет сверху вниз):

| Состояние | Источник | Визуал |
|---|---|---|
| EMPTY | debug | части сетки нет: контур не рисуется, углы-точки |
| BROKEN | debug; каскад при GAME OVER | фрагментированный контур (сегменты с разрывами), мерцание |
| ATTACK | удар проходит через клетку (чип, взрыв, выстрел, волна) | яркая полоса через клетку, акцент или красный, 0,15 с |
| DANGER | телеграф атаки врага | красный контур, пульс, плотный дизеринг |
| SPAWN | появление врага в начале боя | сжимающиеся концентрические квадраты |
| OBJECT | debug | wireframe-куб в клетке |
| ACTIVE | клетка игрока | яркий контур + редкая заливка |
| AFTER | несколько кадров после ATTACK | контур мерцает |
| NORMAL | всегда | тонкий контур |

BROKEN / EMPTY / OBJECT пока только визуал: включаются на любой клетке из DBG; игровые правила панелей — отдельный шаг [решение 2026-09-17].

## 5. Существа

### 5.1. Враги

- Процедурные пиксельные оккультные существа: `seed → 2–3 примитива → симметрия/деформация → пикселизация → красный спрайт` (32×32).
- Примитивы: круги, глаза, щупальца, линии, геометрические фигуры, органы, оккультные символы.
- У каждого врага: крупный силуэт (заполнено ≥ 25% площади), 1 основной цвет (красный), не больше 3 внутренних элементов (дыры фона и один акцент).
- Облик типа фиксирован сидом (`ENEMY_SEEDS`): Mettik, Canodron и Spiker узнаваемы и различимы; DBG может перегенерировать сиды.
- Анимация: покачивание (idle), «вдох» — растяжение в телеграфе, белая вспышка при попадании, распад на пиксели при удалении, концентрические кольца при варпе.

### 5.2. Игрок

- Отдельный нарисованный силуэт 24×32: фосфор + акцентный визор. Мгновенно отличим от врагов и клеток.
- Мигание при неуязвимости; короткий след из линий при шаге; «вдох» при использовании чипа.

## 6. Атаки

Только геометрия: линии, полосы, точки.

| Атака | Визуал |
|---|---|
| Cannon / HiCannon / Shotgun | акцентная линия вдоль линии + ATTACK на поражённых клетках |
| Мечи | дуги из линий на клетках удара |
| MiniBomb | точка по параболе, затем квадратный взрыв (расширяющиеся контуры) |
| Recover | поднимающиеся фосфорные точки над игроком |
| Волна Mettik | красный клин-полоса, бегущий по клеткам |
| Выстрел Canodron | красная линия |
| Прицел Canodron | красные уголки рамки; при захвате сжимаются и мигают |
| Огонь Spiker | красный ромб-«звезда», пульсирует |
| Варп Spiker | красные концентрические кольца в старой и новой клетке |

## 7. HP и урон

- **HP врага** — ряд крупных сегментов над врагом, без подписей: `HP_SEGMENTS` = 8, цена сегмента = max HP / 8; живые сегменты красные, потерянные — тусклый контур.
- **Урон** — крупное пиксельное число (масштаб ×3) в области попадания, поднимается и гаснет: по врагу — акцент, по игроку — красный, лечение — фосфор.
- Рисуются в HUD-слое CRT (2D), позиции — из проекции камеры.

## 8. Бой без текста: графические сигналы

| Было | Стало |
|---|---|
| BATTLE n/4 | сетка «прорисовывается» ряд за рядом от игрока вглубь; враги появляются из SPAWN |
| BATTLE START! | акцентная волна проходит по сетке от игрока вглубь |
| ENEMY DELETED! | клетки врага вспыхивают, сетка пульсирует |
| GAME OVER | каскад BROKEN от игрока, сетка гаснет красным |
| NO CHIP | только отказ EXECUTE на корпусе |
| HP / CUSTOM / имя чипа | только светодиоды корпуса и ряд чипов |

Время сигналов берётся из `world` (тики состояния), поэтому пауза их замораживает.

## 9. Параметры (`tuning.battleVisual`)

| Параметр | Значение | Назначение |
|---|---|---|
| `VIEW_PITCH` | 38 ° | наклон камеры |
| `VIEW_FOV` | 50 ° | вертикальный угол обзора |
| `VIEW_FILL` | 0.92 | доля кадра под поле |
| `CELL_GAP` | 0.08 | зазор между контурами клеток (доля клетки) |
| `SPRITE_CELL_FRAC` | 0.95 | ширина спрайта врага в долях клетки (игрок — 0.8 от неё); тексель округляется до целого пикселя |
| `DANGER_PULSE_HZ` | 6 | пульс опасных клеток |
| `ATTACK_CELL_TIME` | 0.15 с | полоса ATTACK |
| `AFTER_TIME` | 0.2 с | мерцание после атаки |
| `SPAWN_TIME` | 0.6 с | маркеры появления |
| `HP_SEGMENTS` | 8 | сегменты HP врага |
| `DAMAGE_SCALE` | 3 | масштаб чисел урона |
