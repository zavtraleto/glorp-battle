# Glorp Battle — физический боевой терминал (NET-01)

Версия 1.0 · 2026-09-17 · статус: утверждено к разработке

Спецификация интерфейса-«игрушки» вокруг существующего боя. Боевые правила по-прежнему описаны в [GDD.md](GDD.md); этот документ описывает только **как игрок видит бой и управляет им**. При противоречии в вопросах управления и отображения прав этот документ; в вопросах правил боя — GDD.

Источники: «Physical Battle Terminal — Design Document (MVP)», «Visual Style Guide — PS1 Pixel / Low-Poly / Tactile Terminal», концепт-арт NET-01, обсуждение 2026-09-17. Все решения из обсуждения помечены `[решение 2026-09-17]`, оценки — `[оценка]`.

---

## 0. Идея

Игрок находится в неизвестном месте перед старым терминалом и сражается в виртуальном пространстве с порождениями ИИ. Сколько он здесь — неизвестно; возможно, за этим терминалом сменилось много поколений игроков, пытавшихся пройти «игру». Визуально — ретрофутуризм «used future» в духе корабля из фильма «Чужой»: грубая, потёртая, специализированная машина.

**Главный принцип.** Интерфейс — не HUD, а физический аппарат. Цифровой мир виден только внутри CRT; все действия игрока — через материальные органы терминала: чипы, гнёзда, трекбол, кнопки. Физичность — это иллюзия массы, инерции, фиксации и отклика, а не физическая симуляция.

**Критерий успеха.** Игроку хочется повторять ритуал «чип активен → нажал EXECUTE → чип вылетел → сигнал → атака на экране», даже когда он знает, что произойдёт, — и при этом бой не становится медленнее, чем сейчас.

## 1. Границы

**Не меняется:** правила боя (`src/sim`), последовательность боёв и экраны сессии (`src/app`), очередь чипов MMBN1, кастом-шкала, правила кодов, ADD, клавиатурное управление.

**Меняется:** весь слой отображения и ввода. `src/ui` (HTML/CSS) заменяется 3D-терминалом `src/terminal`. Бой (`src/render`) рисуется в текстуру и показывается на экране CRT.

**Единственное изменение логики:** выбор на кастом-экране поддерживает вставку в позицию и извлечение любого выбранного чипа (§6.4).

**Не входит:** физический движок, кабели как система, Navi Customizer, деформация платы вирусами, новые экраны и меню сверх существующих, GLTF-модели и внешние ассеты.

## 2. Принятые решения

| # | Решение | Отличие от исходного PDF |
|---|---|---|
| 1 | Чипы используются строго по очереди MMBN1: активен всегда первый оставшийся слева. Выбора касанием в бою нет. | PDF §3.3 (tap по чипу в бою) — не делаем |
| 2 | Трекбол: **один жест = один шаг**; шар вращается за пальцем и докручивается по инерции. | PDF §3.1 — непрерывное вращение не делаем |
| 3 | Жест начинается в увеличенной зоне вокруг шара и продолжается, даже если палец из неё вышел. | — |
| 4 | Кнопка **CHIP SELECT** — слева от трекбола. Кастом-шкала — **кольцо светодиодов** вокруг неё; когда горят все, загорается и кнопка. Дополнительно шкала — полоса CUSTOM в CRT. | PDF не описывает шкалу |
| 5 | После использования гнездо **пустеет** (видны контакты), активным становится следующий чип справа. Ряд не сдвигается. | — |
| 6 | Кастом-экран: нижняя панель уезжает, на её месте выезжает **лоток** с рукой. На лотке — клавиши **OK** (крупная) и **ADD**. | — |
| 7 | HUD и все меню — **внутри CRT**. HP дублируется рядом зелёных светодиодов на верхней рамке. HTML — только DBG и lil-gui. | — |
| 8 | Вся графика **процедурная** (код + canvas-текстуры), без внешних ассетов. | — |
| 9 | Камера смотрит на терминал **почти фронтально**, узкий FOV. | — |
| 10 | Одна спецификация на весь терминал; релиз этапами T1 → T2 → T3 (§11). | PDF: звук P1 — у нас T3 |
| 11 | Навигация по меню CRT — трекболом, подтверждение — EXECUTE, tap по пункту — ускоритель. Пауза — маленькая физическая кнопка на корпусе. | — |
| 12 | Неиспользованные чипы при открытии кастом-экрана физически выбрасываются из гнёзд («сгорание», GDD §7.2). | — |
| 13 | Внешность Navi, вирусов и иконок — собственная; сходство с Capcom (Mega Man, Mettaur, Canodumb) не допускается, даже если оно есть на концепте. | — |

## 3. Компоновка

Портрет. Терминал занимает весь viewport по высоте. Доли — параметры `tuning.terminal` [оценка, подбираем на телефоне].

```
┌───────────────────────────────────────┐
│ NET-01  PERSONAL NET TERMINAL     [II]│  верхняя рамка ~6%: маркировка, пауза
│ ● ● ● ● ● ● ● ● ● ●                   │  10 LED HP
├───────────────────────────────────────┤
│▐ ┌───────────────────────────────┐ ▌  │
│▐ │ [100]            CUSTOM ▓▓▓░░ │ ▌  │
│▐ │                               │ ▌  │  CRT ~50%
│▐ │        поле боя 3×6           │ ▌  │  лампы POWER/SYNC/LINK/BATTLE,
│▐ │   (враги сверху, Navi снизу)  │ ▌  │  решётки, наклейки
│▐ │                               │ ▌  │
│▐ │ CANNON A                      │ ▌  │
│▐ └───────────────────────────────┘ ▌  │
├───────────────────────────────────────┤
│ [CHIP][CHIP][CHIP][CHIP][CHIP] SLOT5/5│  ряд чипов ~14%
├───────────────────────────────────────┤
│  ◦◦◦◦                                 │
│ ◦┌──┐◦     ╭─────╮      ┌────────┐    │
│ ◦│▣ │◦    │  ●  │      │EXECUTE │    │  нижняя панель ~30%
│ ◦└──┘◦     ╰─────╯      └────────┘    │
│  ◦◦◦◦    NAVIGATION                   │
│ CHIP SELECT                           │
└───────────────────────────────────────┘
```

- Иерархия размеров (гайд §16): CRT > чипы > трекбол ≈ EXECUTE > CHIP SELECT > мелкие элементы.
- Зона нажатия любого органа ≥ 56 CSS px по короткой стороне; зона трекбола — вся левая-центральная часть панели (§5.1).
- Учитываем безопасные зоны экрана (`env(safe-area-inset-*)`): терминал вписывается во внутреннюю область.
- **Широкий экран (ПК, планшет в ландшафте):** терминал вписывается по высоте и стоит по центру; по бокам — тёмная стена отсека с кабелями и трубами (простые формы, почти в темноте).

## 4. Режимы терминала

Режим **не хранится**, а вычисляется каждый кадр из `session.screen` и `world.state` (`terminalMode.ts`).

| Режим | Когда | CRT | Активные органы | Ряд чипов |
|---|---|---|---|---|
| `BATTLE` | `world.state = ACTION` | бой + HUD | трекбол, EXECUTE, CHIP SELECT, пауза | очередь, активный чип |
| `CHIP_SELECT` | `world.state = CUSTOM` | бой (затемнён) + описание чипа | лоток: чипы, гнёзда, OK, ADD; пауза | гнёзда выбора |
| `MENU` | `session.screen ∈ {TITLE, PAUSED, RESULT, DEFEAT, COMPLETE}` | меню | трекбол (курсор), EXECUTE (выбор), tap по пункту | погашен |
| `TRANSITION` | `BATTLE_INTRO`, `BATTLE_START`, `PLAYER_DEAD`, `BATTLE_WON`, анимация выезда/уезда лотка | бой + баннер / помехи | нет (кроме паузы, где её разрешает сессия) | как в предыдущем режиме |

Переход `BATTLE → CHIP_SELECT` явный (CHIP SELECT) и полностью отключает движение, чтобы перетаскивание не конфликтовало с управлением Navi (оно и так отключено: симуляция стоит в `CUSTOM`).

## 5. Органы управления

Общее для всех органов:

- Реакция на `pointerdown` **в том же кадре** (просадка, подсветка). Игровая команда отправляется в тот же момент и выполняется на ближайшем шаге симуляции (≤ 16,7 мс).
- Нажатие отменяется, если указатель ушёл с органа до отпускания, — кроме EXECUTE и CHIP SELECT, у которых действие срабатывает на `pointerdown` (быстрота важнее отмены).
- Недоступное действие даёт «глухое» нажатие: орган проседает меньше, короткая красная индикация, команда не отправляется.
- В режиме `TRANSITION` органы не реагируют.
- Мультитач: каждый палец (`pointerId`) ведёт свой орган; трекбол и EXECUTE можно нажимать одновременно.

### 5.1. Трекбол (NAVIGATION)

- Крупный тёмный шар (сфера 12×8 граней, плоское затенение) в толстом кольце со стрелками ▲▼◀▶.
- **Зона захвата** — вся средняя колонка нижней панели между `DECK_SPLIT_LEFT` и `DECK_SPLIT_RIGHT`, от ряда чипов до низа. Жест, начатый в зоне, продолжается за её пределами до отпускания.
- **Распознавание:** существующий `SwipeRecognizer` — шаг срабатывает сразу при смещении ≥ `SWIPE_MIN_PX` по доминирующей оси; остаток жеста игнорируется до отпускания.
- **Визуал:** с первого пикселя шар поворачивается за указателем (`TRACKBALL_ROLL_GAIN` рад/px), после отпускания докручивается по инерции и затухает (`TRACKBALL_FRICTION`). При срабатывании шага на кольце вспыхивает стрелка направления.
- **Режим BATTLE:** шаг → команда `move(dir)`.
- **Режим MENU:** вверх/вниз → курсор меню; влево/вправо — зарезервировано.
- Клавиатура (WASD/стрелки) также вращает шар и мигает стрелкой — визуально управляет тем же органом.

### 5.2. EXECUTE

- Большая красная кнопка в толстой рамке с жёлто-чёрными полосами и винтами.
- `pointerdown`: кнопка проседает (`BUTTON_PRESS_DEPTH`) и слегка сжимается; `pointerup`: возвращается с коротким перелётом (`BUTTON_OVERSHOOT`).
- Удержание не повторяет действие.
- **BATTLE:** команда `useChip`. Если очередь пуста или чип сейчас нельзя использовать — «глухое» нажатие, CRT коротко показывает `NO CHIP`.
- **MENU:** выбрать пункт под курсором.
- Клавиши Space / F нажимают EXECUTE (с той же анимацией).

### 5.3. CHIP SELECT и кольцо шкалы

- Жёлтая квадратная кнопка с пиктограммой «стопка чипов» слева от трекбола. Вокруг — кольцо из `GAUGE_LEDS` = 12 светодиодов.
- **Кольцо:** горит `floor(gauge × GAUGE_LEDS)` светодиодов (по часовой стрелке от верхнего). При 100% горят все, **загорается сама кнопка**, кольцо медленно пульсирует.
- **BATTLE, шкала полная:** нажатие → команда `openCustom` (как сейчас).
- **BATTLE, шкала неполная:** «глухое» нажатие, погашенные светодиоды мигают красным.
- Клавиши Q / E нажимают CHIP SELECT.

### 5.4. Пауза

- Маленькая утопленная кнопка `II` в правом верхнем углу рамки. Нажатие — пауза / продолжение (как текущая HTML-кнопка).
- Esc — то же. Автопауза при скрытии вкладки и жесте «назад» сохраняется.

### 5.5. Мышь и ПК

Тактильность на ПК обязательна:

- Нажатие и отпускание кнопки мыши = нажатие и отпускание органа, с той же анимацией.
- Трекбол: зажать шар и тянуть; шар вращается за мышью.
- **Наведение:** орган под курсором слегка приподнимается и подсвечивается; чип на лотке приподнимается.
- **Курсор:** пиксельная рука (CSS `cursor` с data-URI, сгенерированным из canvas); при зажатии — «нажимающая» рука; над неактивной областью — обычная.
- **Параллакс:** камера слегка смещается за курсором (`PARALLAX_DEG` = 1,5°), включено по умолчанию только при `pointer: fine`.
- Клавиатура дублирует органы и анимирует их (§5.1–5.4).

## 6. Чипы

### 6.1. Физический чип

- Толстая кассета (скруглённый бокс, 1–2 сегмента фаски), не карточка. Сверху — металлическая скоба, снизу — видимые контакты.
- **Лицо** — canvas 58×72 px, nearest-фильтр:
  - название крупным пиксельным шрифтом (`chipName`, английский);
  - пиксельная иконка 32×32 (собственный рисунок, ограниченная палитра);
  - внизу — буква кода в плашке и мелкая техническая маркировка (урон).
- Текстуры лиц кэшируются по `defId + code`.
- Цвет рамки лица — по типу чипа (атака / меч / бомба / лечение) [оценка].

### 6.2. Состояния

| Состояние | Где | Визуал |
|---|---|---|
| `IDLE` | лоток / гнездо | лежит; в гнезде — приглушён |
| `HOVER` | лоток / гнездо | чуть приподнят (мышь или палец над ним) |
| `DISABLED` | лоток | затемнён, не берётся (правило кодов, GDD §7.3) |
| `DRAGGING` | над терминалом | следует за указателем с небольшим отставанием (пружина), наклоняется по скорости |
| `VALID_DROP` | над гнездом | гнездо подсвечивается, чип притягивается к нему |
| `SNAPPED` | гнездо | резко садится на место (snap), вспышка контактов, щелчок |
| `REJECTED` | → лоток | пружиной возвращается в исходную позицию |
| `ACTIVE` | гнездо | выдвинут на `CHIP_ACTIVE_LIFT`, ярко-зелёная подсветка |
| `USED` | гнездо → камера | анимация вылета (§6.3) |
| `BURNED` | гнездо → вниз | выброс при открытии кастом-экрана (§6.5) |

### 6.3. Ряд чипов в бою

- Пять гнёзд с рамкой и контактами; справа — счётчик `CHIP SLOT n/5` (n — оставшиеся чипы).
- После OK выбранные чипы стоят в гнёздах 1..k слева направо (порядок = порядок использования). Гнёзда k+1..5 пустые.
- **Активный** — первый непустой слева: приподнят, ярко светится; имя и код активного чипа показаны внизу CRT.
- **Использование** (по событию симуляции `chipUsed`, не по нажатию — чтобы визуал совпадал с логикой):

| Шаг | Время (параметр) | Событие |
|---|---|---|
| 1 | 0 | EXECUTE проседает (уже в кадре нажатия) |
| 2 | 0 | `chipUsed`: чип подпрыгивает (`EJECT_LIFT_TIME` 0,06 с) |
| 3 | 0,06–0,40 с | чип летит к камере и вниз: рост масштаба, смещение перспективы, вращение; исчезает (`EJECT_TIME` 0,34 с) |
| 4 | 0–0,25 с | импульс по плате от гнезда к CRT (T3; в T1 — вспышка контактов гнезда) |
| 5 | 0 | атака в CRT идёт сразу, анимация её не задерживает; CRT: короткая вспышка/помеха |
| 6 | 0,10 с | следующий чип справа поднимается в `ACTIVE` |

- Пустое гнездо показывает контактные площадки.

### 6.4. Лоток (кастом-экран)

**Открытие** (при входе `world.state` в `CUSTOM`, в т. ч. автоматически в начале боя):

1. Оставшиеся в гнёздах чипы выбрасываются (§6.5).
2. Нижняя панель уезжает вниз, снизу выезжает лоток (`TRAY_SLIDE_TIME` 0,25 с, с перелётом).
3. На лотке — рука: сетка 5 × (1..3), размер руки по GDD §7.2. Под сеткой — клавиши **ADD** (слева, меньше) и **OK** (справа, крупная, под тем же пальцем, что EXECUTE).
4. CRT: поле затемнено; поверх — крупная иконка, название, код, урон и описание чипа, который последним был под пальцем/курсором (по умолчанию — первый чип руки).

**Выбор:**

- **Tap** по чипу на лотке → чип летит в первое свободное гнездо (порядок = порядок использования) и фиксируется.
- **Drag** чипа на лотке → при отпускании над гнездом `i` чип вставляется в позицию `min(i, k)`, где `k` — число уже выбранных; чипы с этой позиции и правее сдвигаются вправо. Ряд всегда плотный, без дыр.
- **Drop мимо гнёзд** или недопустимый чип → `REJECTED`, возврат на лоток.
- **Извлечение:** tap или drag выбранного чипа из гнезда → чип возвращается на своё место на лотке, чипы правее сдвигаются влево. Подтверждение не требуется. (Заменяет кнопку Cancel из GDD §7.3: извлечение последнего = Cancel.)
- Недопустимые по правилу кодов чипы на лотке — `DISABLED`, пересчёт после каждого изменения (как сейчас).
- Выбор ограничен 5 чипами; при 5 все оставшиеся чипы лотка `DISABLED`.
- **OK** → `world.customConfirm()`; лоток уезжает, панель возвращается, дальше `BATTLE_START`.
- **ADD** → `world.customAdd()`; выбранные чипы возвращаются на лоток, лоток уезжает, ряд пуст.
- Клавиатура (P2): стрелки — курсор по руке, Space — взять, Backspace — извлечь последний, Enter — OK. В T1 достаточно мыши и касаний.

**Изменение логики (единственное):** в `ChipSystem` и `World` добавить

- `selectAt(handSlot, index)` — вставка в позицию `index` (с проверкой допустимости набора; порядок на допустимость не влияет);
- `unselect(index)` — извлечение любого выбранного чипа (подмножество допустимого набора всегда допустимо).

`select(slot)` и `cancelLast()` остаются и выражаются через них. Покрыть тестами в `tests/chips.test.ts`.

### 6.5. Сгорание

При открытии кастом-экрана неиспользованные чипы (GDD §7.2, п. 1) одновременно выскакивают из гнёзд с небольшим разбросом по времени (`BURN_STAGGER` 0,04 с) и падают вниз за край экрана, темнея. Гнёзда пустеют, затем выезжает лоток.

## 7. CRT

### 7.1. Содержимое

**Режим BATTLE:**

| Элемент | Где | Содержимое |
|---|---|---|
| HP | слева сверху | число в рамке; янтарное при HP ≤ 25%, мигает при уроне |
| CUSTOM | справа сверху | надпись + полоса шкалы; при 100% мигает |
| HP врагов | цифра под каждым врагом | переносится из `worldLabels` (T2) |
| Активный чип | внизу слева | `CANNON A` — имя и код; `NO CHIP`, если очередь пуста |
| Баннеры | по центру | `BATTLE n/4`, `BATTLE START!`, `ENEMY DELETED!`, `GAME OVER`, `PAUSED`, `NO CHIP` (0,5 с) |
| Урон | в мире | всплывающие цифры (как сейчас, но пиксельным шрифтом) |

**Режим CHIP_SELECT:** описание чипа (§6.4).
**Режим MENU:** меню (§8).

Весь текст — английский, через `t('key')`.

### 7.2. Реакции на события

| Событие | Реакция CRT |
|---|---|
| `chipUsed` | вспышка яркости + короткая помеха (`CRT_FLASH_TIME` 0,12 с) |
| игрок получил урон | цветовой сдвиг RGB + тряска картинки (не корпуса) 0,15 с |
| враг удалён | короткий всплеск свечения |
| переходы (`TRANSITION`) | помехи и полосы |
| шкала заполнилась | лампа BATTLE на корпусе мигает; полоса CUSTOM мигает |

### 7.3. Светодиоды и лампы корпуса

- **HP:** 10 зелёных светодиодов на верхней рамке; горит `ceil(10 × hp / maxHp)`. При потере погасший светодиод мигает 0,3 с. При HP ≤ 25% оставшиеся горят янтарным.
- **Лампы слева от CRT:** POWER (горит всегда), SYNC (мигает в `TRANSITION`), LINK (горит в бою), BATTLE (горит в `BATTLE`, мигает при полной шкале).
- **Счётчик** `CHIP SLOT n/5` — пиксельный семисегментник рядом с рядом чипов.

## 8. Меню в CRT (T2)

- Экраны сессии: TITLE, PAUSED, RESULT, DEFEAT, COMPLETE — те же пункты и данные, что сейчас в `ui/screens.ts`.

## 9. Рендер и визуальный стиль

### 9.1. Конвейер кадра

1. **Бой → render target** `CRT_RES` = 240×320 [оценка], nearest-фильтр. Существующие `field`, `actors`, `fx` рисуются туда; камера боя подгоняется под соотношение сторон экрана CRT.
2. **HUD/меню → canvas** того же разрешения, пиксельным bitmap-шрифтом. Перерисовка только при изменении отображаемых значений (dirty-флаг).
3. **Терминал → render target пониженного разрешения** (`RENDER_SCALE`: короткая сторона 400 px по умолчанию) → на экран без сглаживания (nearest). Так крупный пиксель получает и корпус.
4. HTML поверх: только кнопка DBG, lil-gui, оверлей статистики.

Один `WebGLRenderer`, `antialias: false`.

### 9.2. Шейдер CRT

Один проход на меше стекла. Входы: текстура боя, текстура HUD, текстура прошлого кадра, импульсы событий.

- Бочкообразная кривизна, виньетка, скруглённые углы.
- Сканлайны и маска фосфора (интенсивность — параметры).
- Лёгкий ghosting (смешивание с прошлым кадром), отключаемый (`CRT_GHOSTING`).
- Color bleed (горизонтальное размытие хромы).
- Блик на стекле.
- Импульсы: `flash`, `noise`, `rgbShift`, `shake` — затухают по времени.

CRT-эффект **не применяется** к корпусу. Картинка CRT ярче и контрастнее корпуса.

### 9.3. Геометрия (PS1 low-poly)

- Процедурные примитивы: скруглённые боксы (1–2 сегмента фаски), `ExtrudeGeometry`, `LatheGeometry`, гранёные сферы.
- Силуэт важнее детализации; допустимы лёгкие неровности и странные пропорции.
- Повторяющиеся детали (винты, светодиоды, решётки, контакты) — `InstancedMesh`.
- Опционально (параметры, по умолчанию выключено): `PS1_VERTEX_SNAP` (дрожание вершин), `PS1_AFFINE` (аффинные текстуры).

### 9.4. Текстуры

- Canvas 64–256 px, генерируются кодом при старте, `NearestFilter`, без mipmap.
- Корпус: грязный пластик/крашеный металл крупными пятнами, потёртости блоками пикселей; тени и AO запечены в текстуры и цвет вершин.
- Маркировка: крупный пиксельный шрифт, слегка кривая, «шелкография» или наклейки.
- PCB: кремово-оливковая подложка, тёмные/медные дорожки с органическими ветвлениями, крупные площадки.
- Иконки чипов, спрайты Navi и врагов — собственный pixel-art с ограниченной палитрой (замена спрайтов-заглушек — T2).

### 9.5. Материалы, свет, цвет

- Корпус и органы — `MeshLambertMaterial` (или простой собственный шейдер) + запечённое затенение.
- Свет: один мягкий направленный + заполняющий ambient + цветной «свет от CRT», чья яркость следует за средней яркостью картинки CRT.
- Светящиеся элементы (LED, активный чип, импульс PCB, подсветка кнопок) — emissive, без отдельных источников.
- Тени: запечённые пятна; у летящего чипа — blob-тень.
- Палитра (гайд §12): основа — charcoal, грязный серый, тёплый серый; старый пластик — кремовый, пожелтевший беж, олива; PCB — приглушённый зелёный, коричневый, медь; CRT — глубокий сине-чёрный + cyan/green/amber; активное — cyan, phosphor green, amber; опасность — red, orange-red. Цвет появляется только там, где терминал активен.

### 9.6. Камера

- Перспектива, почти фронтально, `CAMERA_FOV` ≈ 22° [оценка], наклон `CAMERA_PITCH` ≈ 0–5°.
- Терминал вписывается по высоте с учётом safe area.
- Параллакс от курсора на ПК (§5.5).

### 9.7. Анимация

- Пружины (spring) и твины в `anim/`, без физического движка.
- Характер: крупные читаемые движения, короткий механический перелёт, snap вместо плавного прилегания.
- Декоративное движение можно квантовать до `ANIM_STEP_FPS` (по умолчанию 0 = выкл.) ради PS1-характера. Реакция на ввод не квантуется.

## 10. Производительность

**Цели:** Chrome на Android (основная), Chrome на ПК; 60 FPS минимум, 120 FPS где экран позволяет. Симуляция — 60 Гц, отрисовка — с частотой экрана с интерполяцией (как сейчас).

**Бюджет** (проверяется на шаге T1.1):

| Метрика | Предел |
|---|---|
| Время кадра CPU+GPU, средний Android | ≤ 8 мс |
| Время кадра, ПК | ≤ 4 мс |
| Draw calls | ≤ 150 |
| Треугольники | ≤ 30 000 |
| Память текстур | ≤ 32 МБ |
| Генерация терминала при старте, телефон | ≤ 300 мс |
| Задержка «касание → реакция органа» | тот же кадр |

**Правила:**

- Canvas-текстуры обновляются только по dirty-флагу.
- Raycast / hit-test только на `pointerdown` и `pointermove` при перетаскивании, по списку невидимых зон нажатия (≈ 10–25 объектов); трекбол — 2D-проверка прямоугольника.
- Никаких карт теней, постобработки на весь кадр, динамических источников на объект.
- Без аллокаций в горячем цикле (переиспользуемые векторы).

**Если бюджет не выполняется** (по порядку): уменьшить `RENDER_SCALE` → выключить `CRT_GHOSTING` → уменьшить `CRT_RES` → включить автоматическое понижение качества (по скользящему времени кадра).

  terminalMode.ts      # режим из session.screen + world.state (чистая функция)
  layout.ts            # доли и позиции зон по размеру экрана (чистые функции)

    tray.ts  pcb.ts  environment.ts
  crt/
    battleTarget.ts    # render target боя и подгонка камеры боя
    crtMaterial.ts     # шейдер CRT и импульсы
    crtCanvas.ts       # HUD, баннеры, описание чипа, меню

    icons.ts           # pixel-art иконки чипов

### 13.2. Инварианты

- **Терминал только читает** симуляцию и сессию. Изменения — только через `InputState` (`move`, `useChip`, `openCustom`), `world.custom*()` и действия `Session` — как сейчас в `main.ts`.
- **Режим вычисляется**, а не хранится (§4). Локальные анимационные состояния органов (лоток выезжает) живут в органах и не влияют на логику.
- **Анимации — по событиям симуляции** (`SimEvent`), а не по нажатиям, если визуал должен совпадать с логикой (вылет чипа, урон, удаление). Реакция самого органа — по нажатию.
- **Все числа** — в `tuning.terminal` (секунды, пиксели, доли), редактируются в DBG. Новая группа попадает в GDD §17.
- **Никаких `Math.random()`** в логике; для декоративного разброса допустим отдельный ГСЧ терминала (не влияет на бой).
- **Весь текст** — через `t()`.
- `src/render` не знает о терминале; терминал вызывает `SceneRenderer` для отрисовки в render target.

### 13.3. Поток кадра

```
pointer/keyboard ──► pointerRouter ──► орган (анимация в этом кадре)
                                    └► InputState / world.custom*() / session.*()
GameLoop.tick ──► world.step() ──► SimEvent[] ──► fx (бой) + terminal.onEvents()
GameLoop.render ──► terminal.update(dt, view)
                ──► battleTarget: SceneRenderer.render(alpha) → RT
                ──► crtCanvas.redraw() если dirty
                ──► terminal scene → low-res RT → экран (nearest)
```

### 13.4. Что удаляется / меняется

- `attachSwipe` (глобальный свайп) заменяется трекболом; `blockBrowserGestures`, `trapBackNavigation`, wake lock остаются.
- `src/ui/*` скрывается на T1 и удаляется на T2 (включая `styles.css`, кроме стилей DBG).
- `main.ts` делится: сборка приложения + `terminal`.

## 15. Тестирование

**Vitest (без WebGL):**

- `terminalMode` для всех сочетаний `session.screen` × `world.state`.
- `layout`: зоны не пересекаются, размеры зон нажатия ≥ минимума на 360×640 и 430×932, вписывание в широкий экран.
- Трекбол: жест в зоне → один `move`; жест вне зоны → ничего; выход за зону не прерывает жест.
- Drag: попадание в гнездо → `selectAt` с правильной позицией; промах → возврат; извлечение → `unselect`; недопустимый чип не вставляется.
- `ChipSystem.selectAt` / `unselect`: порядок, сдвиги, допустимость, лимит 5.
- EXECUTE при пустой очереди — «глухое» нажатие, команда не отправлена; CHIP SELECT при неполной шкале — то же.
- Кольцо и LED HP: число горящих диодов по значениям.
- Меню: курсор, границы, выбор.
- Пружины и твины сходятся и не дают NaN при больших `dt`.

**Вручную / в браузере:** Chrome DevTools с эмуляцией телефона (`390x844x3,mobile,touch`) и реальный телефон через GitHub Pages; ПК с мышью.
