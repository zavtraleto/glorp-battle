## 2. Buster

> **Заменено 2026-09-18** ([план run-cleanup-bn3](../plans/2026-09-18-run-cleanup-bn3.md)): Buster удалён целиком, см. GDD §4.

- Модуль `sim/buster.ts`, группа `buster` в `tuning.ts`: `BUSTER_INTERVAL` = 1 с, `BUSTER_DAMAGE` = 1 (базовый Buster MMBN1).
- Таймер идёт только в `ACTION` (по `tick`). Во время анимации чипа (`actionTicks`), оглушения, паралича и заморозки симуляции выстрел не происходит: таймер ждёт готовности, выстрелы не накапливаются (максимум один «готовый» выстрел).
- Выстрел — мгновенный луч вперёд (−y) из клетки игрока по его колонке. Бьёт первую цель: врага или объект (§3.4). Использует тот же поиск цели, что и `shootLane`.
- Событие `busterShot { x, fromY, toY }`. Визуал: короткая линия акцентного цвета; урон — обычная цифра.
- `CLAUDE.md` и GDD: пункт «The Buster is removed» заменяется на описание авто-Buster `[решение 2026-09-17]`.

**Тесты:** интервал выстрелов; нет выстрела во время чипа, оглушения, паралича; попадание в первую цель колонки; попадание в объект; нет накопления выстрелов после блокировки.

## 3. Панели поля

### 3.1 Модель

Класс `Field` (`sim/field.ts`) внутри `World`. Для каждой клетки:

| Поле | Значения |
|---|---|
| `panel` | `NORMAL`, `CRACKED`, `BROKEN` |
| `owner` | `player`, `enemy`; стартовое значение — по ряду (y 0–2 враг, 3–5 игрок) |
| `timer` | тики до восстановления (для `BROKEN` и захваченных клеток) |

API: `panel(x, y)`, `owner(x, y)`, `canStand(side, x, y)`, `crack(x, y)`, `breakPanel(x, y)`, `repair(x, y)`, `setOwner(x, y, side)`, `onLeave(x, y)`, `update()`.

### 3.2 Правила

- **CRACKED → BROKEN**, когда стоявший на клетке персонаж (игрок или враг) уходит с неё. Тяжёлый удар (Quake1, ядро Helmhead, удар Monolith) ломает клетку сразу.
- На **BROKEN** нельзя встать никому. Через `PANEL_RESTORE_TIME` `[оценка 10 с]` клетка становится `NORMAL`.
- Под персонажем или объектом дыра сразу не появляется: `crack` на занятой клетке ставит `CRACKED` как обычно, а `breakPanel` на занятой клетке тоже ставит только `CRACKED` (дыра — после ухода).
- **Волны** (ShockWave, волна Mettik, удар Monolith) обрываются на дыре. Лучи, Buster и броски дыр не замечают.
- **Захват:** меняет владельца свободных клеток. Клетку под врагом или объектом захватить нельзя. Через `STEAL_RESTORE_TIME` `[оценка 15 с]` владелец возвращается к исходному, если клетка свободна; иначе — при первом освобождении (по MMBN3, в MMBN1 правило не описано).
- Ходить можно только по своим клеткам: `Player.canStep` и `Enemy.tryStep` / `warpTo` проверяют `field.canStand(side, x, y)` вместо `inTerritory` и жёсткого `ny > 2`.
- Все таймеры панелей идут по `tick` и замирают вместе с симуляцией.

### 3.3 События и визуал

- Событие `panelChanged { x, y, panel, owner }`.
- `render/cellStates` берёт `BROKEN` и владельца из `world.field`; debug-переопределения (DBG → Field) остаются поверх.
- `CRACKED` — новое визуальное состояние: контур с трещиной-изломом (фосфор или красный по владельцу).
- Раскраска клеток — по владельцу, а не по номеру ряда: захваченная клетка рисуется фосфором, граница территорий — по фактическому владельцу.

### 3.4 Объекты

- Объект (`sim/object.ts`) — сущность с HP в `Occupancy`, без ИИ. Поля: `id`, `x`, `y`, `hp`, `side` (кто поставил).
- Загораживает клетку, принимает попадания лучей, Buster, чипов и атак врагов. При HP 0 удаляется (событие `objectBroken`).
- RockCube: HP `[оценка 100]`. Визуал — существующее состояние `OBJECT`.

**Тесты:** трещина → дыра после ухода; нельзя шагнуть на дыру; дыра восстанавливается по таймеру; волна обрывается на дыре; захват пропускает занятую клетку и возвращается по таймеру; объект блокирует выстрел и разрушается.

## 4. Чипы из строительных блоков

### 4.1 Описание чипа

`pattern` в `data/chips.ts` заменяется составным описанием:

```ts
interface ChipDef {
  id: ChipId;
  power: number | null;
  useTime: UseTimeGroup;
  kind: 'attack' | 'support' | 'field';
  /** Коды, из которых выбирается код награды. */
  codes: ChipCode[];
  rarity: 'common' | 'uncommon' | 'rare';
  shape: Shape;
  onHit?: { push?: true; paralyze?: true; panel?: 'crack' | 'break' };  // длительность паралича — PARALYZE_TIME
  field?: FieldAction;
  heal?: number;
  invis?: true;                  // длительность — INVIS_TIME
}

type Shape =
  | { t: 'lane'; around?: Cell[] }            // первая цель в колонке + клетки относительно неё
  | { t: 'near'; cells: Cell[] }              // клетки относительно игрока
  | { t: 'lob'; depth: number; area: Cell[] } // бросок на depth клеток вперёд + область
  | { t: 'wave' }                             // волна по колонке до края поля или дыры
  | { t: 'self' };

type FieldAction = 'crackRow' | 'crackAll' | 'breakEnemy' | 'steal' | 'repair' | 'rock';
```

Смещения клеток заданы относительно направления игрока (вперёд = −y). `abbr` и `color` уходят: лица кассет генерируются по `id`.

### 4.2 Исполнение

- `resolveChip` применяет по порядку: `shape` → урон → `onHit` к каждой поражённой цели/клетке → `field` → `heal` / `invis`.
- `patterns.ts` — чистая функция `shapeCells(shape, px, py, lookup)`: для `lane` и `lob` возвращает клетки урона, для `wave` — стартовую клетку.
- `wave` порождает атаку-сущность; `sim/attacks/shockwave.ts` обобщается, чтобы её могли пускать и игрок (вниз по вражеской территории, −y), и враги (+y).
- `lob` остаётся задержанной атакой, как `bomb.ts`, с областью вместо одной клетки.
- Событие `chipEffect` получает поле `shape` вместо `pattern`; визуал рисует след по клеткам.

### 4.3 Новые состояния

- `Enemy.paralyzeTicks`: враг не действует, его таймеры состояния стоят. Удары по нему проходят.
- `Enemy.push(ctx)`: сдвиг на ряд назад (−y), если клетка своя, свободна и не `BROKEN`; иначе ничего.
- `Player.invisTicks`: удары врагов проходят сквозь игрока (как `invulnerable`, но без мигания от урона; визуал — редкий дизеринг спрайта).

- 10 шагов. На шагах 1–9 из сида генерируются 2–3 варианта (`normal` или `elite`); элитные — не раньше шага 3 `[оценка]`. Шаг 10 — всегда босс.
- Вариант показывает тип и число врагов; состав скрыт.
- Встреча выбирается сидом из пула по типу и `depth`, без повторов в одном забеге.
- Экран **PATH** — на CRT, по правилам меню (TERMINAL.md §8): трекбол и EXECUTE или касание пункта. Сверху: `STEP 04/10`, HP, размер папки.

### 6.3 Награда

> **Заменено 2026-09-18** ([план run-cleanup-bn3](../plans/2026-09-18-run-cleanup-bn3.md)): наград и экрана REWARD нет, лоток удалён (GDD §10.3).

- Экран **REWARD** — на лотке: лоток выезжает с тремя кассетами. Касание кассеты — описание на CRT; OK — забрать (кассета «уезжает» в терминал); клавиша ADD подписана SKIP.
- Выбор трёх чипов сидом: обычный бой — веса по редкости `[оценка common 70 / uncommon 25 / rare 5]`; элитный — минимум одна кассета uncommon или выше. Код — сидом из `codes`.
- SKIP ничего не даёт.

### 6.4 Смерть и наследие

> **Заменено 2026-09-18** ([план run-cleanup-bn3](../plans/2026-09-18-run-cleanup-bn3.md)): наследия, поколений и экрана LEGACY нет; смерть и ABANDON ведут на GAME_OVER → TITLE (GDD §10.4).

- RETRY убирается. После сигнала поражения — экран **LEGACY** на CRT: прокручиваемый список папки с курсором; выбранный чип «остаётся в терминале».
- `src/app/legacyStore.ts` (localStorage, try/catch, ключ с версией) хранит `{ chip, code, gen }` и счётчик поколений. При недоступном хранилище игра работает без наследия.
- На титуле — `GENERATION 07`. Следующий забег добавляет чип-наследие в стартовую папку; на кассете метка `GEN 07`; запись удаляется при старте забега.
- Если новый игрок тоже погибает, он снова выбирает наследие; у чипа-наследия метка сохраняет исходное поколение.
- Победа над боссом — экран **COMPLETE** со статистикой; наследие за победу не выдаётся.
- Пауза получает пункт ABANDON: забег считается смертью → LEGACY.
