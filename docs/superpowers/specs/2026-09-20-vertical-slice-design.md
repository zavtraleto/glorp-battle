# Вертикальный срез боя — дизайн [2026-09-20]

Замена всего боевого контента Glorp Battle на ограниченный набор из семи врагов и десяти чипов, пригодный для полировки real-time боя. Источник требований — `MMBN6_vertical_slice_gameplay_spec.md` (далее «спека среза»), референс — MMBN6.

Связанные документы: [GDD](../../GDD.md) (§6–7 чипы, §8 враги, §9 урон, §10 забег, §17 тюнинг), [BATTLE_VISUAL.md](../../BATTLE_VISUAL.md) (§5 спрайты, §10.1 карта кода), [TERMINAL.md](../../TERMINAL.md) (§6.1 иконки чипов).

---

## 1. Задача

Прототип накопил девять врагов и двадцать семь чипов, но ни один боевой цикл не отполирован: нет Counter, тайминги врагов живут в разнородных группах тюнинга, у чипа ровно один кадр удара, а понять «почему меня ударило» нечем.

Срез меняет приоритет: **меньше контента, больше качества боевого языка**. После этой работы в игре остаются ровно семь семейств врагов и десять чипов, у каждой атаки есть явные фазы, у каждого подходящего врага — окно Counter, а у разработчика — инструмент, показывающий причину любого попадания.

Спека среза требует **заменить** контент, а не дополнить (§6 спеки). Это решение принято.

### Что проверяет срез

Движение и его предсказуемость, чтение telegraph, реакцию на projectile, melee range, тайминг чипов, состояния врага, area denial, forced movement и осознанный Counter. По одному навыку на врага (§19 спеки).

## 2. Рамки

### Входит

- семь семейств врагов, по одной базовой версии каждого;
- десять чипов;
- система Counter;
- единая модель фаз атаки для врагов и чипов (§16 спеки);
- debug-инструмент «почему меня ударило»;
- три пресета папок: BASIC, CONTROL, RANDOM;
- забег из десяти шагов без босса, по лестнице появления врагов из §4 спеки.

### Не входит [решение 2026-09-20]

- стихии и слабости, статусы сверх паралича;
- уровни вирусов 2 и 3 (механизм `ENEMY_LEVELS` остаётся в коде, контент его не использует);
- Navi-чипы, Mega/Giga, Program Advances;
- Folder building как система;
- AreaGrab в поведении Bladdy (§3.3 спеки называет его опциональным);
- рисованный арт для четырёх новых врагов — отдельная работа после полировки паттернов;
- новые звуки сверх уже имеющихся.

## 5. Модель данных: фазы атаки (§16 спеки)

### 5.1. Профиль врага

Спека среза требует единый набор полей. У каждого врага — своя группа в `src/config/tuning.ts` с **одинаковыми именами полей**: дебаг-панель обходит группы автоматически, а один диапазон в `RANGES` начинает работать на всех врагах сразу.

```ts
mettik: {
  HP: 40,
  DMG: 10,
  KNOCKBACK: 0,        // рядов отдачи цели, 0 = нет
  MOVE_INTERVAL: 0.5,
  TELEGRAPH: 0.5,      // от начала замаха до commit
  COUNTER: 0.25,       // хвост окна Counter (§6)
  ACTIVE: 0.2,         // сколько живёт хитбокс
  RECOVERY: 1.5,
  WAVE_STEP: 0.25,     // специфика врага — сверх профиля
},
```

Обязательные для всех: `HP`, `DMG`, `KNOCKBACK`, `TELEGRAPH`, `COUNTER`, `ACTIVE`, `RECOVERY`. `MOVE_INTERVAL` — у всех, кто ходит. Остальные ключи — свои у каждого врага.

**`commit` — это конец `TELEGRAPH`**: момент, когда атака спавнится и уклониться уже нельзя. Отдельного поля `COMMIT` нет, оно вычисляется.

Базовый `Enemy` получает:

```ts
protected get p(): EnemyProfile   // группа тюнинга этого врага
counterOpen(tick: number): boolean
```

и сам считает границы фаз. Классы врагов худеют до «куда хожу» и «что спавню»; арифметика таймингов уходит в базу. `this.ticks()` и `this.dmg()` сохраняются — уровни остаются механизмом, просто не используются контентом.

### 5.2. Тайминг чипа

`CHIP_USE_TIME_<группа>` и глобальный `CHIP_HIT_FRAME` удаляются. Чип получает **класс тайминга** из §6 спеки, а числа классов живут в тюнинге:

```ts
// data/chips.ts
{ id: 'vulcan', timing: 'FAST', hits: 3, ... }

// config/tuning.ts
chipTiming: {
  FAST_STARTUP: 0.06,   FAST_HIT_STEP: 0.05, FAST_RECOVERY: 0.18,
  MEDIUM_STARTUP: 0.15, MEDIUM_RECOVERY: 0.30,
  SLOW_STARTUP: 0.30,   SLOW_RECOVERY: 0.45,
},
```

`HIT_STEP` заводится только у класса, в котором есть многоударный чип: сейчас это только FAST (Vulcan). Если многоударный чип появится в другом классе — он приносит свой ключ.

Иерархия из §7 спеки (`Vulcan < Sword/WideShot < Cannon/MiniBomb` по startup и commitment) держится тремя ручками, а не двадцатью. Значения выше — стартовые [оценка], их и полируем.

`ActiveChip` получает **массив** `hitTicks` вместо одного `hitTick`:

```
startTick
  ├─ startup ─→ hit[0]
  │              ├─ hitStep ─→ hit[1] … hit[hits-1]
  └───────────────────────────── recovery ─→ endTick
```

Игрок заблокирован от `startTick` до `endTick`. Каждый удар — собственный реестр попаданий, поэтому multi-hit честно бьёт одну цель несколько раз. Из этого бесплатно получается Vulcan.

Поля `ChipDef`, которых требует §16 спеки: `timing` (startup/active/recovery), `hits`, `shape` (hitbox и targeting), `power` (damage), `onHit.push` (knockback), `field` (fieldEffect). Скорость и время жизни снаряда — в `Shape`.

## 6. Counter

Полностью новая система. По §9 спеки Counter — отдельный навык тайминга, а не случайный бонус за попадание.

### Окно

Каждая атака хранит окно отдельно. По умолчанию **окно Counter — последние `COUNTER` секунд состояния `TELEGRAPH`**, то есть непосредственно перед commit.

Исключение — Stovik: у него окно открыто в начале `ATTACK` («после начала атаки», §9 спеки). Фаза окна задаётся константой класса, не тюнингом:

```ts
protected counterPhase: 'telegraph' | 'active' = 'telegraph';
```

| Враг | Окно | Источник |
|---|---|---|
| Mettik | обязательно, хвост телеграфа | §9 спеки |
| Bladdy | обязательно, хвост телеграфа | §9 спеки |
| Rollik | обязательно, хвост телеграфа (момент сворачивания) | §9 спеки |
| Canodron | есть, хвост задержки после лока | §9 спеки: «желательно» |
| Pirak | есть, хвост задержки после лока | §9 спеки: «желательно» |
| Stovik | начало `ATTACK` | §9 спеки |
| Gustbox | нет (`COUNTER: 0`) | §9 спеки |

### Срабатывание

`World.damageEnemy(enemy, amount, source)` получает источник урона (`'chip' | 'other'`). Counter засчитывается, когда одновременно: `source === 'chip'`, окно открыто и удар **действительно нанёс урон** — по защищённому врагу (`guarded`) Counter не проходит. Тогда:

1. атака **не спавнится** (или мгновенно гаснет, если окно было в `ACTIVE`);
2. враг переходит в `RECOVERY` и парализуется на `counter.PARALYZE`;
3. эмитится событие `countered` — вспышка CRT, свой звук, цифра урона другим тоном;
4. игрок получает `syncTicks = counter.SYNC_TIME`: **следующий чип бьёт ×`counter.DAMAGE_MULT`**.

Синхро сгорает при использовании чипа, по истечении таймера или при попадании по игроку.

```ts
counter: {
  PARALYZE: 1.5,
  SYNC_TIME: 5.0,
  DAMAGE_MULT: 2,
},
```

Это наш аналог Full Synchro: буквальное воспроизведение механики MMBN6 не требуется (§2 спеки), нужна награда за тайминг, которая толкает к связке «Counter → тяжёлый чип».

## 7. Три новых механизма

### 7.1. Зона (`ZoneAttack`)

Новый тип `Attack` в `src/sim/attacks/zone.ts`: живёт на фиксированном наборе клеток `ACTIVE` секунд и чистит свой реестр попаданий каждые `RE_HIT` секунд.

При `PLAYER_IFRAMES` = 2 с стояние в зоне само собой даёт не больше одного удара в две секунды — модель честная и не требует отдельного анти-спам-правила.

Зона ничего не блокирует и не останавливает снаряды. Используется дважды:

- **Stovik** — огненная зона, длинная;
- **Bladdy** — взмах меча, короткий.

Bladdy переводится на неё специально ради §3.3 спеки: сейчас его удар мгновенный в конце телеграфа, а анимация `enemySlash` живёт `SLASH_TIME` — то есть хитбокс и визуал не совпадают. После перевода хитбокс живёт ровно `ACTIVE` и совпадает с тем, что видно.

### 7.2. Forced movement

```ts
Player.forcedStep(dir: Dir): boolean
```

Игнорирует `MOVE_COOLDOWN` и буфер, но уважает `field.canStand` и занятость клетки. **Не сбрасывает собственный кулдаун игрока** — ветер не крадёт ход. Обновляет `prevX/prevY/lastMoveTick`, поэтому рендер интерполирует сдвиг как обычный шаг.

Если шаг невозможен (край поля, дыра, занято) — ничего не происходит, урона нет.

### 7.3. Barrier

```ts
Player.barrierHp: number
```

Поглощает урон, пока не кончится. Попадание в барьер **не даёт** flinch, i-frames и не прерывает чип — барьер именно переживает угрозу, а не заменяет уклонение. Остаток барьера виден на CRT рядом с полосой HP.

Gustbox сдувает барьер первым же толчком (§3.7 спеки). `chips.BARRIER_HP` — тюнинг.

## 8. Семь врагов

Общее для всех: живут в своей территории (`y ∈ 0..2`), автомат `IDLE → MOVE → TELEGRAPH → ATTACK → RECOVERY`, попадание не прерывает действие, телеграф подсвечивает клетки через `dangerCells()`.

### 8.1. Mettik — базовый тайминг

Функция по §3.1 спеки: первый враг, на котором игрок понимает, что можно не убегать, а ждать момент атаки.

Поведение сохраняется: держит свой ряд, шагает вбок к колонке игрока каждые `MOVE_INTERVAL`; выровнявшись и владея токеном хода — `TELEGRAPH` → волна вниз по колонке → `ACTIVE` → `RECOVERY` → передаёт токен. Очередь хода между несколькими Mettik (`hasTurn` / `passTurn`) остаётся: один Mettik бьёт постоянно, несколько — по очереди (§3.1 спеки).

Меняется: переход на стандартные имена профиля и окно Counter.

### 8.2. Canodron — projectile / реакция

Стационарен. Пока игрок в его колонке, пускает курсор вниз по колонке (`CURSOR_STEP`); дойдя до ряда игрока — лок; через `TELEGRAPH` — мгновенный выстрел по колонке; `ACTIVE`, `RECOVERY`. Уход из колонки до лока отменяет курсор без кулдауна.

`CANO_FIRE_DELAY` переименовывается в `TELEGRAPH`, `CANO_COOLDOWN` — в `RECOVERY`.

Требование §3.2 спеки — причина урона всегда «я остался в линии» — выполняется курсором и локом. Скорость выстрела не трогаем: он мгновенный, читаемость держится на длине `TELEGRAPH`.

### 8.3. Bladdy — melee range

Идёт в колонку игрока и к переднему краю своей территории; на месте — `TELEGRAPH` → `ZoneAttack` на двух клетках перед собой (`y+1`, `y+2`) на `ACTIVE` → `RECOVERY`.

Меняется: удар становится зоной с настоящим окном (§7.1), чтобы хитбокс не жил дольше и не появлялся раньше визуала.

### 8.4. Pirak — target lock / prediction

Новый. Ходит вдоль **своего ряда** (`x ± 1`) каждые `MOVE_INTERVAL`. Дойдя до колонки игрока, ставит курсор на его клетку и **фиксируется**: держит `LOCK_TIME`, затем `TELEGRAPH`, затем пускает стрелу (`LaneShot`) вниз по своей колонке со скоростью `SHOT_STEP`; `ACTIVE`, `RECOVERY`.

Ключевое: **после лока Pirak не отменяет атаку**, даже если игрок ушёл из колонки. Колонка зафиксирована в момент лока, выстрел состоится в любом случае, и Pirak до конца выстрела не двигается.

Главное отличие от Canodron (§3.4 спеки): Canodron сбрасывает курсор, как только игрок вышел из линии — угроза читается как «линия, из которой надо выйти». Pirak фиксирует цель и обязуется выстрелить — угроза читается как «меня выбрали, у меня есть `LOCK_TIME + TELEGRAPH`, чтобы изменить ситуацию». Это разные навыки, и оба должны быть в игре.

Синхронизация залпа (§3.4 спеки): лок одного Pirak переводит остальных живых Pirak в `TELEGRAPH` по их текущим колонкам. Для этого `EnemyContext` получает `alliesOfKind(kind): Enemy[]` — прецедент уже есть в виде `hasTurn`/`passTurn` у Mettik.

### 8.5. Rollik — состояния и броня

Новый. Четыре фазы, читаемые снаружи:

```
FOLLOW   — шагает по своему ряду к колонке игрока
ALIGN    — в колонке; TELEGRAPH: сворачивается. УЯЗВИМ, здесь окно Counter
ARMORED  — guarded = true, катится вниз по колонке, шаг за ROLL_STEP
RECOVERY — разворачивается, guarded = false, возвращается наверх
```

Во время `ARMORED` он **остаётся на поле и видим**: удары по нему дают событие `guarded` (отскок), а не урон. Это выполняет требование §3.5 спеки — состояние очевидно по модели, а не по невидимому флагу.

Чтобы катиться по чужим панелям, `tryStep` получает опцию `anySide`. Если следующая клетка занята игроком — Rollik наносит `DMG`, останавливается и уходит в `RECOVERY` там же. Игрок в этот момент в i-frames и может отойти.

Объехать Rollik можно вбок — он едет строго по своей колонке.

### 8.6. Stovik — area denial

Новый. Почти неподвижен. Цикл:

```
ROTATE    — меняет ориентацию каждые ROTATE_INTERVAL
TELEGRAPH — сопло раскаляется, dangerCells = будущая зона
ATTACK    — ZoneAttack на ACTIVE секунд; окно Counter в начале этой фазы
RECOVERY
```

Две ориентации (§3.6 спеки в нашей портретной геометрии):

| Ориентация | Клетки | Что вынуждает |
|---|---|---|
| `ALONG` | `(x, y+1)`, `(x, y+2)`, `(x, y+3)` | закрыта одна колонка — уходи вбок |
| `ACROSS` | весь ряд `y+1` | закрыт один ряд — отходи назад |

Стихий нет (§3.6 спеки): цвет пламени — только визуал, слабостей и урона панелям не вводим. Единственный игровой эффект — area denial.

### 8.7. Gustbox — forced movement

Новый. Стационарен, HP выше среднего, **урона не наносит** (§3.7 спеки). Цикл:

```
TELEGRAPH — раскрутка, чтобы включение не было внезапным
ATTACK    — ветер ON, ACTIVE секунд: каждые PUSH_INTERVAL
            игрок сдвигается на одну панель к заднему ряду (+y)
RECOVERY  — ветер OFF
```

Первый толчок сдувает Barrier. Если игрок уже в заднем ряду, толчок не делает ничего — это не урон и не наказание.

`COUNTER: 0` — Gustbox не counter-враг.

**Порядок работ обязателен:** Gustbox делается последним из врагов, после полировки движения (§3.7 и §11 спеки). Ветер поверх нестабильного управления замаскирует проблему вместо того, чтобы её показать.

| MiniBomb | SLOW | `lob` depth 3 | 50 | 1 | delayed, максимальный commitment |
| AreaGrab | MEDIUM | `self` + `field` | — | — | глобальное изменение пространства |
| PanlGrab | MEDIUM | `self` + `field` | — | — | локальное изменение пространства |
| Barrier | MEDIUM | `self` | — | — | defensive timing |
| Recover | MEDIUM | `self` | — | — | resource decision, heal 50 |

Урон — MMBN3/MMBN6 по существующему правилу проекта. Классы таймингов — из §6 спеки, отношения — из §7.

### Новая форма `shot`

```ts
{ t: 'shot'; width: number }
```

Снаряд игрока: летит по колонке вверх со скоростью `SHOT_STEP`, накрывает `width` клеток поперёк (`x−1, x, x+1` при width 3), бьёт каждую цель один раз, гаснет на краю поля. Реализация — `src/sim/attacks/playerShot.ts` на базе `LaneMover`, чтобы FX интерполировали полёт.

Форма `wave` удаляется вместе с чипом ShockWave.

### Новое поле `barrier`

`ChipDef.barrier?: number` — сколько урона поглощает. Единственный носитель — Barrier.

## 10. Папки

Folder building не тестируется как система (§15 спеки). Три пресета, размер папки остаётся 30 карт, правило совместимости кодов (GDD §7.3) не трогаем.

| Пресет | Состав | Цель |
|---|---|---|
| **BASIC** | Cannon, Vulcan, WideShot, Sword, WideSwrd, MiniBomb, Barrier, Recover | чистый action |
| **CONTROL** | то же + AreaGrab, PanlGrab | positioning + field manipulation |
| **RANDOM** | случайный набор из тех же десяти | не ломается ли петля боя при непредсказуемом наборе |

Папка `field` удаляется, `FolderId` становится `'basic' | 'control' | 'all'`. `randomFolder` продолжает работать: лимит копий поднимается так, чтобы десяти чипов хватало на тридцать карт.

Титульный экран: три кнопки — Basic / Control / Random. Ключи `title.field` → `title.control`.

## 13. Debug

Правило проекта «в бою на CRT нет текста» сохраняется. Инструмент делится надвое.

### На CRT — только цвет

- хитбоксы живых атак (включая зоны);
- клетка игрока как hurtbox;
- открытое окно Counter — отдельной меткой на враге.

Метки включаются вместе с DBG и не влияют на обычный рендер.

### В DOM — текст

Новый `src/debug/combatOverlay.ts` рядом с существующим FPS-оверлеем:

- строка на живого врага: `kind · state · кадр/всего · counter?`;
- лог последних попаданий по игроку: кто, чем, в каком состоянии был враг, было ли открыто окно Counter.

Это закрывает §10 спеки: при каждом получении урона видно enemy, attack, hitbox, hurtbox, attack state и кадр.

## 14. Правила честности (§10 спеки)

Проверяются на каждой атаке и фиксируются тестами:

1. **Хитбокс не опережает визуал.** Атака спавнится ровно в конец `TELEGRAPH`; первый урон — не раньше следующего тика после спавна.
2. **Урон не приходит после конца визуала.** Зона исчезает и перестаёт бить в один и тот же тик.
3. **Recovery — настоящее состояние.** Ни у одного врага `RECOVERY` не равно нулю: перехода из атаки сразу в новую атаку не бывает.
4. **Снаряд читаем.** Видимый спавн, одно направление, постоянная скорость, стабильный хитбокс. Снаряды не меняют направление.
5. **Каждая атака врага имеет telegraph.** Атака без `dangerCells()` — ошибка теста.
